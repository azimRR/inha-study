    What is an algorithm? [D01-S2–S7]

    An algorithm = exact steps a computer follows to solve a problem.

    • 5 properties (F-U-D-I-F): Finiteness, Unambiguous, Definiteness of sequence, Input/Output defined, Feasibility.
    • 7 techniques: Divide & Conquer, Greedy, Branch & Bound, Backtracking, Dynamic Programming, Brute Force, Randomized.

    Example Sequential search on [7, 3, 9, 5]: K = 9 → index 2. K = 4 → −1.

    In plain words

    An algorithm is an exact list of steps that a computer follows to solve a problem.

    Example

    Sequential search. You have an unordered array E = [7, 3, 9, 5] and a key K. Look at each entry from left to right. If you find K, return its index. If you reach the end, return −1.

    K = 9 → returns 2. K = 4 → returns −1.

    Counting work: basic operation and W(n) [D01-S8, S9, S17, S18]

    Count the most important operation. W(n) = the biggest count for any input of size n.

    • Sequential search: W(n) = n (K last, or not there).
    • Binary search (sorted array): W(n) = ⌈lg(n+1)⌉, optimal.
    • findMax: always n − 1.

    Example [7, 3, 9, 5], K = 4 → 4 comparisons = n. Binary search with n = 1000 → 10.

    In plain words

    Pick the one operation that matters most and count how many times it runs. The worst case W(n) is the largest count over all inputs of size n.

    Example

    Sequential search on E = [7, 3, 9, 5] (n = 4). The basic operation is "compare K with an array entry".

    KComparisonsReturns
    710
    932
    5 (last position)43
    4 (not in the array)4−1

    The worst cases cost 4 = n. So W(n) = n. They happen when K is only in the last position or not in the array at all.

    Formal (slide)

    Let Dn be the set of inputs of size n, and t(I) the number of basic operations performed on input I.

    W(n) = max{ t(I) | I ∈ Dₙ }, called the worst-case complexity.

    "The input, I, for which an algorithm behaves worst depends on the particular algorithm." [D01-S18]

    A good measure of work [D01-S17]

    • Tells us about the efficiency of the method.
    • Is independent of computer, programming language, programmer and other implementation details.
    • Usually depends on the size of the input.
    • Count passes through loops, or count a basic operation: "the total number of operations performed is roughly proportional to the number of basic operations".

    Binary search: "The Best possible solution?" [D01-S9]

    On an ordered array, binary search needs at most W(n) = ⌈lg(n+1)⌉ comparisons. The slide says in bold: "The Binary Search algorithm is optimal."

    Example: n = 1000 → ⌈lg 1001⌉ = 10, because 2⁹ = 512 < 1001 ≤ 1024 = 2¹⁰. Sequential search could need 1000.

    Correctness and loop invariants [D01-S10–S16]

    A loop invariant is a sentence that stays true every time the loop goes around.

    • Prove 3 things: Initialization (true at the start), Maintenance (stays true each round), Termination (at the end it gives the answer).
    • Contrapositive: "if A then B" = "if not B then not A".

    Example get_max, invariant "max = biggest of a[0..i−1]". On [4, 9, 2, 7, 5]: max goes 4 → 9 → 9 → 9 → 9.

    Correctness can be proved [D01-S10]: if the preconditions are satisfied, then the postconditions will be true when the algorithm terminates.

    In plain words

    A loop invariant is a true/false sentence about the loop that stays true every time the loop goes around. If it is still true at the end, the loop did its job.

    Example

    The professor's notes use a magic trick: a ball is hidden under one of three cups and the cups are moved around. "The ball is under one of the cups" is true before the trick, after every move, and at the end. That sentence is the invariant.

    get_max on a = [4, 9, 2, 7, 5]. Invariant: "max is the maximum value in a[0..i−1]".

    • Start, i = 1: max = 4, the maximum of a[0..0] = [4]. True.
    • After checking a[1] = 9: max = 9, the maximum of [4, 9]. Still true.
    • After 2, 7 and 5: max stays 9. At the end i = len(a), so max = 9 is the maximum of the whole array.
    Formal (slide)

    To prove correctness with a loop invariant we show three things [D01-S12]:

    1. Initialization: the invariant is true prior to the first iteration of the loop.
    2. Maintenance: if it is true before an iteration, it remains true before the next iteration.
    3. Termination: when the loop terminates, the invariant along with the reason the loop terminated gives us a useful property.

    A loop invariant is a property of type boolean and must be aligned with the goal of the algorithm.

    def get_max(a):            # [D01-S13]
  max = a[0]
  for i in range(1,len(a)):
    if a[i] > max:
      max = a[i]
  return max
    Stepget_max proof, as on the slides [D01-S13, S14]
    Invariant"max is the maximum value in a[0..i-1]"
    Initializationi = 1, the scope is a[0..1−1] = a[0], and max = a[0]. Invariant holds.
    MaintenanceIf max is the maximum of a[0..k−1], the next iteration compares and possibly updates max with a[k], so max is the maximum of a[0..k]. Invariant holds.
    Terminationi = len(a), so max is the maximum of a[0..len(a)−1], the whole array.

    Linear search and the contrapositive [D01-S15, S16]

    The output is correct if: (1) when index i is returned, A[i] = x; (2) when Not-Found is returned, x is not in the array.

    Invariant: "At the start of each iteration of step 1, if x is present in the array A, then it is present in the subarray A[i:n]." (A[i:n] means A[i] up to A[n−1].)

    • Initialization: i = 0, so the subarray is A[0:n], the whole array. True.
    • Maintenance: if we do not return, A[i] ≠ x, so if x is in the array it is in A[i+1:n]. Then i goes up by one.
    • Termination: if A[i] = x, we return i (condition 1). If the loop runs out, i = n and A[n:n] is empty, so x is not in it.

    Now use the contrapositive, which the slide puts in a box: "if A then B" ≡ "if not B then not A". The invariant becomes "if x is not present in A[i:n], then x is not present in A". So returning Not-Found is correct (condition 2).

    Space usage [D01-S19]

    Fixed part = same size always. Variable part = grows with the input.

    • Slide line to quote: "Generally we do Time and Space Tradeoff."

    Example Classifying texts: the collection's name is fixed; the text itself (2GB vs 1MB) is variable.

    In plain words

    Some memory stays the same size whatever the input (fixed part). Some memory grows with the input (variable part).

    Example

    A program classifies texts. The name of the data collection takes the same space for 2GB or 1MB of text: fixed part. The actual text takes 2GB or 1MB: variable part.

    Formal (slide)

    Fixed part: "The size required to store certain data/variables, that is independent of the size of the problem".

    Variable part: "Space needed by variables, whose size is dependent on the size of the problem".

    Worst-case analysis can also be done for space, if the memory used depends on the particular input. In large red text: "Generally we do Time and Space Tradeoff."

    Optimality [D01-S26–S29, hidden slides]

    Optimal = best possible, not best known.

    • Find your algorithm's worst case WA(n).
    • Prove the lower bound W[A](n) for every algorithm of that kind.
    • Equal → optimal. Not equal → a better algorithm or a better lower bound may exist.

    Example Binary search is optimal. findMax always does n − 1 comparisons.

    In plain words

    An algorithm is optimal if no algorithm of the same kind can do it with fewer operations in the worst case. It means best possible, not just the best anyone has found so far.

    Example

    findMax on [4, 9, 2, 7, 5] makes 4 comparisons and returns 9. In fact every input of size n costs exactly n − 1 comparisons, because the loop runs n − 1 times with one comparison each. So WA(n) = n − 1, and every input is a worst case.

    int findMax(int[] E, int n)
1. int max;
2. max = E[0];  // Assume the first is max.
3. for (index = 1; index < n; index++)
4.     if (max < E[index])
5.         max = E[index];
6. return max;
    Formal (slide)

    "An algorithm is optimal if there is no algorithm in the class under study that performs fewer operations (in worst case)." "Optimal doesn't mean best known but it means best possible."

    How to show it [D01-S27]:

    1. Analyze algorithm A and find its worst case WA(n).
    2. Prove that every algorithm in the same class must do at least W[A](n) on some input of size n (the lower bound in the worst case).
    3. If WA(n) == W[A](n), A is optimal. Otherwise there may be a better algorithm, OR a better lower bound.

    The deck stops after step 1 for findMax. It does not prove the lower bound, so do not claim more than WA(n) = n − 1 from the slides.

    Math toolkit [D01-S20–S25]

    Small tools you use when counting.

    • Subsets of an n-set: 2ⁿ. Of size k: C(n, k) = n!/((n−k)!k!).
    • Floor rounds down, ceiling rounds up: ⌊2.7⌋ = 2, ⌈2.7⌉ = 3, ⌊−2.7⌋ = −3.
    • Change of base: logc x = logb x / logb c.
    • 1 + 2 + … + n = n(n+1)/2.  1 + 2 + 4 + … + 2k = 2k+1 − 1 (starts at i = 0).

    Example log₄ 64 = lg 64 / lg 4 = 6 / 2 = 3. A 5-element set has 32 subsets, 10 of size 3.

    Sets and counting

    • A set is a collection of distinct elements with no order. e ∈ S means "e is a member of S". ∅ is the empty set, and ∅ ⊆ S for every S.
    • Intersection S ∩ T = elements in S and T. Union S ∪ T = elements in S or T.
    • A set with n elements has 2ⁿ subsets, and C(n, k) = n! / ((n−k)! k!) subsets of size k.

    Example: {a, b, c} has 2³ = 8 subsets. It has C(3, 2) = 3 subsets of size 2: {a,b}, {a,c}, {b,c}.

    Inequalities, floor and ceiling

    Transitivity: A ≤ B and B ≤ C ⇒ A ≤ C. Addition: A ≤ B and C ≤ D ⇒ A + C ≤ B + D. Positive scaling: A ≤ B and α > 0 ⇒ αA ≤ αB.

    Floor ⌊x⌋ is the largest integer ≤ x. Ceiling ⌈x⌉ is the smallest integer ≥ x.

    Logarithms (b > 1, x > 0)

    • logb x = L means bL = x. logb 1 = 0, logb b = 1.
    • logb xa = a·logb x, and logb(xy) = logb x + logb y.
    • xlog y = ylog x.
    • Change of base: logc x = logb x / logb c.
    • log is strictly increasing and one-to-one.

    Examples: lg 8 = 3 because 2³ = 8. log₄ 64 = lg 64 / lg 4 = 6 / 2 = 3. 8lg 4 = 8² = 64 = 4³ = 4lg 8.

    Abstract data types (ADT) [D02-S2–S8]

    ADT = WHAT (data + operations). Data structure = HOW (arrays, pointers, linked nodes).

    • Spec = calling prototype + preconditions + postconditions.
    • Constructor creates · access function reads, no change · manipulation procedure changes, returns nothing.
    • Recursive ADT: an access function returns the same type.

    Example List ADT: cons = constructor; first and rest = access functions (precondition: list ≠ nil).

    In plain words

    An ADT says WHAT data you keep and WHAT you can do with it. A data structure is HOW it is really built in memory.

    Example

    A stack ADT says you can push and pop. It does not say how. The data structure behind it could use an array, pointers or linked nodes.

    Formal (slide)

    "An ADT describes a set of objects sharing the same properties and behaviors." The properties are its data; the behaviors are its operations or functions. "Thus, an ADT couples its data and operations." [D02-S2]

    "Abstraction: hide implementation details." "A data structure is the physical implementation of an ADT."

    Specification of an operation [D02-S6]

    It describes how the operations behave in terms of Inputs and Outputs. It has three parts:

    1. Calling prototype: the name of the operation, its parameters and their types, and the return value and its type.
    2. Preconditions: statements assumed to be true when the operation is called.
    3. Postconditions: statements assumed to be true when the operation returns.

    The ADT catalogue [D02-S9–S15]

    Each ADT has its own in/out rule.

    • Stack = LIFO. Queue = FIFO.
    • Priority queue: cost view removes the smallest, profit view the largest.
    • Union-Find: union joins two sets, find returns the set id (the leader).
    • Binary tree: n nodes → height ≥ ⌈lg(n+1)⌉ − 1.

    Example Push 10, 20, 30 → pop gives 30. Queue gives 10. 20 nodes → height ≥ 4.

    In plain words

    Each ADT has its own rule for where items go in and come out.

    Example
    • Stack: insert 10, 20, 30. Deleting gives 30, then 20, then 10.
    • Queue: insert 10, 20, 30 at the rear. Deleting from the front gives 10, then 20, then 30.
    • Priority queue: insert priorities 5, 2, 8. Cost view removes 2 first; profit view removes 8 first. Arrival order does not matter.
    Formal (slide)
    • Stack: insertions and deletions at one end, the top. Policy: last in, first out (LIFO). [S10]
    • Queue: insert at the rear (back), delete at the front. Policy: first in, first out (FIFO). [S11]
    • Priority queue: order depends on priority, not arrival time. Only the most important element can be inspected and removed: the smallest priority (cost viewpoint) or the largest (profit viewpoint). [S12]

    Binary tree [D02-S9]

    A binary tree is empty, or it has a root r and the other nodes split into two disjoint binary trees L (left subtree) and R (right subtree). The definition is recursive.

    Union-Find for disjoint sets [D02-S13, S14]

    • Union combines two disjoint sets with ids s and t (s ≠ t). The two old sets are removed and the new set is added. The new id is either s or t (in some cases min(s, t)).
    • Find returns the current set id of an element. The set id is a particular element of the set, called the leader.

    Trace with "new id = min(s, t)":

    Dictionary [D02-S15]: a general associative storage structure. Items have an identifier and associated information. No order is implied for the identifiers.

    Counting steps in a model [D03-S2–S8]

    • Slide counts: A=B+C*D-F = 3 · A[I]=B[I]+C[I] = 4 · C=A[I,J] = 4.

    Big-O: the ceiling [D03-S10, S11]

    O = ceiling. f(n) ≤ c·g(n) from n₀ on.

    • c = front number + 1.
    • Subtract the big term from both sides.
    • Test n = 1, 2, 3 … The first ✅ is n₀ (and it must stay ✅).

    Example 3n² + 5 ≤ 4n² → 5 ≤ n² → n = 1 ✗, 2 ✗, 3 ✅ → c = 4, n₀ = 3. Also 8n³ + 6n + 8 → c = 9, n₀ = 3.

    In plain words

    Big-O is a ceiling. From some point n₀ on, f(n) never goes above c·g(n).

    Example

    f(n) = 3n² + 5. The recipe:

    1. Keep the biggest term without its number: g(n) = n².
    2. Take c = leading coefficient + 1 = 3 + 1 = 4.
    3. Write f(n) ≤ c·g(n): 3n² + 5 ≤ 4n².
    4. Subtract the leading term 3n² from both sides: 5 ≤ n².
    5. Test n = 1, 2, 3, …: n = 1 → 5 ≤ 1 ✗ · n = 2 → 5 ≤ 4 ✗ · n = 3 → 5 ≤ 9 ✓. The first true n is n₀ = 3, and it stays true because n² keeps growing.

    Answer: 3n² + 5 = O(n²), c = 4, n₀ = 3.

    Formal (slide)

    O(g(n)) = {f(n) : ∃ positive constants c and n₀, such that ∀n ≥ n₀, we have 0 ≤ f(n) ≤ c·g(n)}

    g(n) is an asymptotic upper bound for f(n): the set of functions that grow at the same rate or slower than g(n).

    The same recipe on the Assignment 1 function

    f(n) = 8n³ + 6n + 8. c = 8 + 1 = 9. 8n³ + 6n + 8 ≤ 9n³ ⇔ 6n + 8 ≤ n³.

    n = 1 → 14 ≤ 1 ✗ · n = 2 → 20 ≤ 8 ✗ · n = 3 → 26 ≤ 27 ✓ ⇒ O(n³), c = 9, n₀ = 3.

    Useful extras

    • Any valid (c, n₀) pair is correct. The professor's notes prefer a small c for O, because it is a tighter ceiling. [D03-S11 notes]
    • Shortcut: c = sum of all coefficients, n₀ = 1. Valid but loose. Example: 3n + 5 ≤ 3n + 5n = 8n for n ≥ 1.
    • Negative terms, for O: just drop them. 5n² − 2n ≤ 5n², so c = 5. [D03-S12 notes]
    • D03-S11 exercise: 3n³ = O(n⁴) with c = 3, n₀ = 1 (or c = 1, n₀ = 3).

    Big-Ω: the floor [D03-S12]

    Ω = floor. f(n) ≥ c·g(n) from n₀ on.

    • c = front number, n₀ = 1 (when the other terms are positive).
    • Negative term? Pay for it from the big term: 5n² − 2n ≥ 3n² → c = 3.

    Example 8n³ + 6n + 8 ≥ 8n³ → c = 8, n₀ = 1.

    In plain words

    Big-Omega is a floor. From n₀ on, f(n) never goes below c·g(n).

    Example

    f(n) = 8n³ + 6n + 8. Take c = the leading coefficient = 8. The other terms are positive, so 8n³ ≤ 8n³ + 6n + 8 for every n ≥ 1.

    Answer: Ω(n³), c = 8, n₀ = 1.

    With a negative term you cannot just drop it. "Pay" for it with part of the leading term: 5n² − 2n ≥ 5n² − 2n² = 3n², so c = 3.

    Formal (slide)

    Ω(g(n)) = {f(n) : ∃ positive constants c and n₀, such that ∀n ≥ n₀, we have 0 ≤ c·g(n) ≤ f(n)}

    g(n) is an asymptotic lower bound for f(n). The notes prefer a large c for Ω, because it is a tighter floor. [D03-S11 notes]

    Big-Θ: both at once [D03-S13–S17]

    Θ = both O and Ω.

    • c₁ a bit smaller than the front number, c₂ a bit bigger.

    Example 10n² − 3n: c₁ = 9, c₂ = 11, n₀ = 3.

    In plain words

    Θ means f(n) is squeezed between a floor and a ceiling of the same shape. Prove O and Ω, and you have Θ.

    Example

    10n² − 3n = Θ(n²) [D03-S15]. Make c₁ a little smaller and c₂ a little bigger than 10.

    • c₂ = 11: 10n² − 3n ≤ 11n² for all n ≥ 1.
    • c₁ = 9: 9n² ≤ 10n² − 3n ⇔ 3n ≤ n² ⇔ n ≥ 3.

    Answer: c₁ = 9, c₂ = 11, n₀ = 3. (Another valid answer: c₁ = 7, c₂ = 10, n₀ = 1.)

    Formal (slide)

    Θ(g(n)) = {f(n) : ∃ positive constants c₁, c₂, and n₀, such that ∀n ≥ n₀, we have 0 ≤ c₁g(n) ≤ f(n) ≤ c₂g(n)}

    g(n) is an asymptotically tight bound. Theorem [D03-S17]: f(n) = Θ(g(n)) iff f(n) = O(g(n)) and f(n) = Ω(g(n)). So Θ(g) = O(g) ∩ Ω(g).

    "To compare orders of growth, look at the leading term." [D03-S15]

    Incorrect bounds, o and ω, properties [D03-S18–S27]

    Compare the biggest powers like numbers a and b.

    • O → ≤ · Ω → ≥ · Θ → = · o → < · ω → >.
    • Wrong bound? Divide by g(n). Keeps growing → not O. Goes to 0 → not Ω.
    • O = worst case, Ω = best case.

    Example f = 2n⁴ + 3n, g = n³ (4 > 3): f = o(g) ✗ wrong · f = Ω(g) ✅ right (c = 2, n₀ = 1).

    In plain words

    A bound is wrong when no constant c can ever make the inequality hold for all large n. Divide both sides by g(n) and look at what is left.

    Example
    • 27n² + 16n + 25 ≠ O(n). Suppose 27n² + 16n + 25 ≤ cn. Divide by n: 27n + 16 + 25/n ≤ c. The left side keeps growing, so it fails once n > c/27.
    • 7n + 5 ≠ Ω(n²). Divide by n²: (7n + 5)/n² ≤ 12/n, which drops below any c once n > 12/c.
    • 5n + 8 ≠ Θ(n²). It is O(n²) but not Ω(n²). Θ needs both, so it fails.
    Formal (slide)

    Proof by contradiction: assume c and n₀ exist, then find an n ≥ n₀ that breaks the inequality. For a false Θ, show one half fails (theorem on D03-S17).

    From recursive code to a recurrence [D04-S2–S8]

    T(n) = (number of calls) × T(new size) + (work in one call).

    • print + demo(n−1) → T(n−1) + 1 → O(n)
    • print + demo(n/2) → T(n/2) + 1 → O(log n)
    • loop to n + demo(n−1) → T(n−1) + n → O(n²)
    • print + 2 × demo(n−1) → 2T(n−1) + 1 → O(2ⁿ)
    • loop to n + 2 × demo(n/2) → 2T(n/2) + n → O(n log n)

    Example Watch the braces: only print is inside the loop on D04-S7, S8.

    T(n) = (how many recursive calls) × T(smaller size) + (work done in this call).

    Recursion tree [D04-S10; Assignment 1 Q4]

    Level cost = (nodes on the level) × (work per node). Add all levels, including the leaves.

    • Costs shrink → root wins → n² · all equal → n log n · costs grow → leaves win → n.
    • T(n−1) trees have n levels, not log n.

    Example 2T(n/2) + n: n per level × log n levels → n log n. 2T(n−1) + 1: 1 + 2 + … + 2ⁿ⁻¹ = 2ⁿ − 1.

    In plain words

    Week 2 keywords

    Big-O (O)
    Asymptotic upper bound: 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀. A ceiling.
    Big-Omega (Ω)
    Asymptotic lower bound: 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀. A floor.
    Big-Theta (Θ)
    Asymptotically tight bound: c₁g(n) ≤ f(n) ≤ c₂g(n). Θ = O ∩ Ω.
    c and n₀
    The constant multiplier and the starting point after which the inequality always holds.
    little-o / little-ω
    Like a < b / a > b: strictly lower / strictly higher order.
    Complementarity
    f = O(g) iff g = Ω(f); f = o(g) iff g = ω(f).
    Recurrence
    T(n) written in terms of T on smaller sizes plus the work in one call.
    Back substitution
    Keep replacing T(…) by its formula until the pattern shows, then stop at the base case.
    Recursion tree
    Each call is a node; sum each level, then sum the levels including the leaves.
    Decreasing / dividing
    Size goes down by subtraction T(n−b) / by division T(n/b).
    [a, b, k, p]
    Calls, divide factor, power of n, power of log in the extra work.
    Not applicable
    a or b not constant, a < 1, k < 0, or a negative driving function.

    Answer

    O: c = 6 + 1 = 7. 6n³ − 4n + 5 ≤ 7n³ ⇔ 5 − 4n ≤ n³. n = 1: 1 ≤ 1 ✓, and it stays true. ⇒ O(n³), c = 7, n₀ = 1. (Also valid: c = 6, n₀ = 2, because the negative term helps: 5 ≤ 4n.)

    Sorting and its categories [D06-S1–S3]

    Sorting puts items in order, so searching becomes Θ(log n) instead of Θ(n).

    Insertion sort [D06-S4–S9]

    Take the next number, shift the bigger ones right, drop it into the gap.

    • Best Ω(n) (already sorted) · worst O(n²) (reversed).
    • Worst count F(n) = n(n−1)/2.
    • Binary search or a linked list still leaves O(n²).

    Example 7, −5, 2, 16, 4 → −5 2 4 7 16 with 7 comparisons and 4 shifts.

    In plain words

    Like sorting cards in your hand: take the next card, slide the bigger cards one step right, and drop the card into the gap.

    Divide → Conquer (recursively) → Combine.

    Split a big problem into smaller copies of itself, solve those, and put the answers together.

    Quicksort and PARTITION [D07-S4, S5]

    Pivot = last element. Small ones go left, then the pivot goes right after them.

    • x = A[r], i = p − 1 = 0, j goes 1 … r−1.
    • If A[j] ≤ x: i++ and swap A[i] ↔ A[j].
    • End: swap A[i+1] ↔ A[r], return q = i + 1.

    Example 18 7 12 15 22 10 → 7 10 12 15 22 18, q = 2.

    In plain words

    How fast is quicksort? [D07-S11–S21]

    Halves → fast. One side gets everything → slow.

    • Worst: T(n−1) + n → Θ(n²), on an already sorted input.
    • Best: 2T(n/2) + n → Θ(n log n). Median pivot or (n/4)-th pivot → n log n too.
    • Sorted vs reversed: T1 = T2. Space: O(log n) balanced, O(n) unbalanced.

    Example 1 2 3 4 5 6: splits 5:0, 4:0, … → 5+4+3+2+1 = 15 comparisons.

    In plain words

    Quicksort is fast when the pivot splits the array into two similar halves, and slow when one side gets almost everything.

    Example

    Sorted input 1 2 3 4 5 6. The pivot is always the largest value, so the splits are 5:0, 4:0, 3:0, 2:0, 1:0. Comparisons = 5 + 4 + 3 + 2 + 1 = 15 = n(n−1)/2.

    Reversed input 6 5 4 3 2 1 also gives fully unbalanced splits and 15 comparisons. So T1 = T2.

    Balanced partitioning → asymptotically as fast as merge sort. Unbalanced partitioning → asymptotically as slow as insertion sort. [D07-S11]

    Versions of quicksort [D07-S6–S10]

    They only change which element becomes the pivot.

    • Randomized: random element → swap to the end → PARTITION. RANDOM(a, b) has b − a + 1 values.
    • Median-of-3: middle of 3 random elements → swap to the end → PARTITION.
    • V2: i from the left, j from the right, swap; when they cross, swap A[i] with the last.

    Example 23 67 12 89 34 95: plain pivot 95 → 5:0 split. Median of 23, 67, 34 = 34 → 2:3 split.

    In plain words

    All versions only change which element becomes the pivot. They move it to the last position and then run the normal PARTITION (V2 uses two pointers instead).

    Example

    Median-of-3 on 23, 67, 12, 89, 34, 95 [D07-S10]. Plain PARTITION picks 95 (the largest), a 5 : 0 split, the worst case. With random positions i = 1, j = 2, k = 5 the values are 23, 67, 34. The middle value is 34, so l = 5. Exchange A[6] ↔ A[5] → 23 67 12 89 95 34. PARTITION → 23 12 34 89 95 67, q = 3, a 2 : 3 split.

    Formal (slide)
    • Randomized quicksort [S6]: i ← RANDOM(p, r), exchange A[r] ↔ A[i], return PARTITION(A, p, r). RANDOM(a, b) returns one of the b − a + 1 integers from a to b.
    • Median-of-3-Partition [S9]: pick three random positions i, j, k; l = the index of the middle value (j tested first, then i, then k); exchange A[r] ↔ A[l]; PARTITION. "In general this algorithm gives very good results except for few cases." It "will dilute the worst sequence" [S10].
    • Median Method V2 [S7, S8]: (1) choose a random pivot; (2) swap it with the last element; (3) i moves right while elements are less than the pivot; (4) j moves left while elements are more than the pivot; (5) exchange A[i] and A[j] when both stop (i < j); (6) when i > j, swap A[i] with the last element.

    Traps and slide errors

    Read these before the exam

    • PARTITION start values: on a 1…n sheet, i = p − 1 = 0 and j starts at p = 1. (On a 0-based sheet: i = −1, j from 0.) The professor's sample wrote "J=0, I=−1", which are the 0-based values.
    • The test is A[j] ≤ x, not <. The sample wrote "A[j] < x". With a key equal to the pivot the two give different arrays.
    • The final exchange is A[i+1] ↔ A[r], and q = i + 1. The sample marked "i" there.
    • The pivot is the last element A[r]. Stop after the first PARTITION if that is all the question asks.
    • Quicksort's worst input is the sorted array, which is insertion sort's best input. Sorted and reversed take the same time: T1 = T2.
    • D07-S4, S6: the two recursive calls are printed level with "if", but they belong to the then-branch.
    • D06-S8 labels the best case "W(n) = Omega(n)". W is the worst-case label; read it as "best case = Ω(n)".
    • D06-S3 lists quicksort under "External". Give the slide's answer if asked about the table.
    • D07-S9: "else if if(" has a stray "if". Read "else if (".
    • D07-S15, S16: "medium" means median. D07-S18: "ration 1:4" means the parts n/4 and 3n/4 (one quarter against three quarters).
    • D07-S7 (V2): rules 3–4 say i < j but rule 6 says i > j. Read it as: once the pointers cross, swap A[i] with the last element. Despite the name, no median is computed; the pivot is random.
    • "Main recurrence theorem" on D07-S13 means the Master theorem.
    • Counting insertion-sort comparisons: only count A[i] > key tests that are made. Reaching i = 0 makes no comparison.
