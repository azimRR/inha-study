/* counter_race2.c — two processes, one shared counter, NO lock */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>
#include "shared_mem.h“
//some library industry offers us
#define N 10
int main(void) {
    long *counter = shared_alloc(sizeof(long));
    /* seen by parent AND child */
    *counter = 0;
    pid_t pid = fork();
    for (int i = 0; i < N; i++)
         /* BOTH processes run this loop */
        (*counter)++;
    if (pid == 0) exit(0);             /* child: done */
    wait(NULL);                        /* parent: wait for the child */
    printf("expected %d, got %ld\n", 2 * N, *counter);
    return 0;
}
What it does
One long in shared memory, set to 0.
fork(): now two processes see the same counter.
Each adds 1.
The parent waits for the child and prints.
What the machine showed
About half of the additions disappeared. Nobody crashed, nothing printed an error, the
result is nondeterministic.

Race Condition & Critical Section
A race condition is an undesirable situation that occurs when a system’s behavior
depends on the sequence or timing of uncontrollable events, such as the execution
order of multiple threads or processes.
Why They Are Dangerous
Race conditions are among the most frustrating bugs to diagnose because they are
intermittent and difficult to reproduce (where the teacher spends hours to
prove the point).
